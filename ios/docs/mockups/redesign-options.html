Redesign options

Three directions for the native app. All keep Berry Cream (the ADR 0001 backgrounds and tokens), target iOS 26 Liquid Glass chrome, and cover the full Organized Glitter feature set except the randomizer. Each one maps to stock SwiftUI views: TabView with a search tab, large-title NavigationStack, List(.insetGrouped), Menu, Form sheets with detents, and ContentUnavailableView. None needs a custom card system.

Where it is todayAudit highlights

The full write-up is in redesign-audit.md, next to this file. These are the problems that make the app feel janky.

Every screen has two titles. The inline nav title and the Caveat PageHeader both say "Library", and together they use about 150pt before any content appears.

Search sits above the page title. .searchable puts the field in the nav bar, and the Caveat title is scroll content, so the order reads upside down.

Five tabs, and two of them aren't destinations. Create is an action, and three of its four rows are disabled "Soon" stubs. Randomizer is out of scope for v1.

Two design languages. Create still uses sticker cards with hard offset shadows and outlines, while Overview and Library are flat and quiet.

The gallery is ragged. Artwork is scaled to fit inside a 170–230pt flexible frame, so tiles end up different heights, and "No artwork" boxes take up as much space as real art.

Filters look like text fields. "All statuses" and "Wishlist" are full-width menu buttons that read as form inputs instead of controls.

The detail screen is thin. It shows a 160pt crop, a second large title, and three rows. There are no progress notes, dates, company, artist, or tags, and changing status means opening the full editor.

iPad has two sidebars. Library's NavigationSplitView sidebar sits inside a .sidebarAdaptable TabView, which already has its own sidebar.

Grids download full-size originals. artworkURL doesn't pass a thumb, and the thumb sizes the editors ask for aren't on the backend's allowlist.

Account deletion is a mailto link. App Store guideline 5.1.1(v) requires deletion to start inside the app. This is already listed as a release blocker.

Option ASettled: Settings and Notes native

Closest to Apple's own apps and cheapest to build. System type everywhere, with Caveat kept only for the wordmark. Lists instead of cards, and artwork as thumbnails. It's calm, dense, and fast for a crafter checking in between rows. The risk is that it can feel plain for a hobby app.

Tabs

Home · Library · Notes, plus a search tab (Tab(role: .search)). Account opens from the avatar button on Home.

Create

A + toolbar Menu on Home and Library: New diamond project, New coloring book, Log progress.

SwiftUI

Stock List, .navigationTitle large, Picker(.segmented), Menu for status. Almost no custom views.

Deletes

PageHeader, SectionHeader, QuietActionStyle, the whole sticker system, LibraryGalleryCard.

Option BShelf: artwork first, like Books and Music

Your kits and books are the interface. Covers get consistent 4:5 frames, carousels, and a full-bleed detail hero with glass controls floating over it. Caveat is the large-title face, used once per screen and never twice. This is the warmest and most "Organized Glitter" option. It depends on good artwork, so the no-artwork state needs care.

Tabs

Home · Library · Notes, plus search. Account opens from the avatar button.

Create

A + toolbar menu, plus a glass "Log" button on each cover in Continue.

SwiftUI

ScrollView(.horizontal) with .scrollTargetBehavior(.viewAligned), LazyVGrid, and .backgroundExtensionEffect() (iOS 26, availability-gated) for the hero.

Cost

Caveat large titles need UINavigationBarAppearance. Otherwise keep system large titles and drop Caveat.

Option CJournal: progress first, like Journal and Reminders

Built around what PRODUCT.md says users do most: short, frequent sessions to log progress. A persistent "Log progress" accessory sits above the tab bar. Projects uses Reminders-style smart lists for the status spine. Caveat appears only as month headers in the journal, which feels personal without looking like a craft store.

Tabs

Today · Projects · Journal, plus search. Account opens from the avatar button.

Log accessory

.tabViewBottomAccessory is iOS 26 only. On iOS 18, gate it with #available and fall back to a toolbar +.

SwiftUI

LazyVGrid smart-list tiles, a List with a custom month Section header, and a timeline built with plain HStacks.

Risk

Browsing the stash and wishlist is one tap deeper than in A or B.

Any optionShared screens

These screens look the same whichever direction you pick. Forms, settings, and sheets should be stock iOS, with the Berry Cream background behind them.

iPadOne sidebar, not two

Use TabSection("Library") inside the .sidebarAdaptable TabView, so the craft list becomes sidebar rows and the nested NavigationSplitView goes away. Shown with Option B's grid; A and C swap in their own content.
